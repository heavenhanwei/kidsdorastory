# Bunny 公园探险 · Demo 需求文档

版本：v1.0　｜　日期：2026-10-11

---

## 1. 概述

这个 Demo 用一个网页，在比赛现场用约 6 分钟演完 5 岁小作者在公园里的一整天：

- 和 AI 伙伴 Bunny 一起发现东西；
- 用英文说一说；
- 集卡；
- 晚上看一本由她自己的发现生成的绘本入睡。

能用嘴说的地方都用语音，只有拍照、看卡、看绘本这些必须看的环节才用手机或 iPad。网页中间是一个 3D 公园。它有两个作用：让评委看到孩子在哪里发现了什么，也让孩子对自己的发现留下空间记忆。

### 1.1 Demo 要证明的三件事

1. **孩子愿意开口**：每次发现后，孩子至少跟着说出一个英文词；或者用中文回答，由 Bunny 接住。
2. **发现会变成"我的"**：孩子能在 3D 地图和绘本里认出自己找到的东西。
3. **出意外也接得住**：孩子不说话、说中文、识别失败，体验都不会中断。

### 1.2 观看对象与时长

| 项目 | 内容 |
| --- | --- |
| 观看对象 | 比赛评委、其他参赛选手（会场大屏）；小作者本人可能现场参与 |
| 完整流程 | 约 6 分钟，小作者在台上不超过 5 分钟 |
| 自动播放版本 | 约 3 分钟，孩子不上台时使用 |

## 2. 演示故事线

演示分七幕，按一天的时间顺序进行，3D 场景的光线从下午逐渐变成夜晚。现场演示时，第 2–5 幕循环 2 次（找两样东西），其余每幕只走一次。

```
 16:30 家门口          公园（循环 2 次）                      19:30 客厅     20:30 卧室
 ┌──────┐   ┌──────┐   ┌──────┐   ┌──────┐   ┌──────┐   ┌──────┐   ┌──────┐
 │ 1    │──▶│ 2    │──▶│ 3    │──▶│ 4    │──▶│ 5    │──▶│ 6    │──▶│ 7    │
 │ 出门 │   │ 发现 │   │ 拍照 │   │ 对话 │   │ 得卡 │   │ 回家 │   │ 睡前 │
 └──────┘   └──────┘   └──────┘   └──────┘   └──────┘   └──────┘   └──────┘
                ▲                                │
                └──────── 还要继续找 ────────────┘
   光线：  下午暖白  ───────────▶  傍晚橙色  ──────────────────▶  夜晚
```

| 幕 | 名称 | 时间与地点 | 发生了什么 | 时长 |
| --- | --- | --- | --- | --- |
| 1 | 出门 | 16:30，家门口 | Bunny 用语音说出今天的任务："去公园找一找会飞的和会动的东西吧！" | 20 秒 |
| 2 | 发现 | 公园 | 孩子看到东西，喊"Bunny，快看！"，3D 镜头飞到那样东西前 | 15 秒 |
| 3 | 拍照 | 公园 | 大人用手机对准拍一下，屏幕出现取景框和识别结果 | 15 秒 |
| 4 | 对话 | 公园 | 孩子和 Bunny 用语音来回 3 轮：跟读单词、二选一、一个短句 | 60 秒 |
| 5 | 得卡 | 公园 | 卡片在手机上翻开，3D 地图上那个位置亮起一颗星 | 15 秒 |
| 6 | 回家 | 19:30，客厅 | 在 iPad 上翻图鉴；Bunny 用语音问"最喜欢哪一张？"，孩子用语音回答 | 45 秒 |
| 7 | 睡前 | 20:30，卧室 | iPad 上播放生成的绘本，一张图一句话，自动翻页；读完关灯，只剩声音 | 90 秒 |

时长计算：20 + (15 + 15 + 60 + 15) × 2 + 45 + 90 ≈ 6 分钟。

## 3. 交互方式分配

原则是**能说就不点**。4–6 岁的孩子不识字，手指操作也不精准，语音是他们最自然的表达方式。只有三类事情必须用屏幕：

- 拍照（要对准）；
- 得卡（要看见奖励）；
- 看图鉴和绘本（要看图）。

户外用大人拿着的手机，在家用孩子可以自己捧着的 iPad。

| 幕 | 孩子怎么交互 | 设备 | 为什么这样分配 |
| --- | --- | --- | --- |
| 1 出门 | 只听，不操作 | 手机外放 | 任务只是一句话，不需要看 |
| 2 发现 | 语音："Bunny，快看！" | 手机（大人拿着） | 孩子的手和眼睛留给真实世界，喊一声就能把 Bunny 叫来 |
| 3 拍照 | 大人按一个大按钮 | 手机 | 对准物体必须看屏幕；孩子手小，户外由大人拿手机更安全 |
| 4 对话 | 语音，3 轮来回 | 手机外放 + 麦克风 | 学英语的核心是开口说；对话期间屏幕只显示 Bunny 在听，不需要点任何东西 |
| 5 得卡 | 看一眼，听一声音效 | 手机 | 奖励要看得见；看完就收起手机，孩子继续玩 |
| 6 回家 | 手指滑动翻卡 + 语音回答 | iPad | 屏幕大、孩子能自己捧着；翻卡是这个年龄能完成的简单手势 |
| 7 睡前 | 只看和听，自动翻页 | iPad，关灯后转为纯声音 | 睡前不需要操作，注意力放在故事上；关灯后不看屏幕 |

```
            语音为主                    屏幕为主
  ┌───────────────────────────┐  ┌───────────────────────────┐
  │ 1 出门   听任务            │  │ 3 拍照   手机（大人按）    │
  │ 2 发现   "Bunny，快看！"   │  │ 5 得卡   手机（看一眼）    │
  │ 4 对话   3 轮来回          │  │ 6 回家   iPad（滑动翻卡）  │
  │ 7 关灯后 纯声音            │  │ 7 睡前   iPad（自动翻页）  │
  └───────────────────────────┘  └───────────────────────────┘
```

**语音唤醒的方式**：Demo 中用"Bunny"作为唤醒词，同时在手机上保留一个大的"按住说话"按钮作为备用。户外噪音大、孩子发音不准时，大人可以按住按钮让孩子说。

## 4. 语音交互设计

每次对话固定 3 轮，每轮 Bunny 只说 1–2 句话，然后等孩子回答。孩子不管说英文、说中文还是不说话，都有对应的接法，对话一定能走完并得到卡片。

### 4.1 三轮对话结构（以珠颈斑鸠为例）

| 轮 | Bunny 说 | 期待孩子说 | 孩子说中文时 | 孩子不说话时（等待 5 秒） |
| --- | --- | --- | --- | --- |
| 1 命名 | "哇，是一只斑鸠！英文叫 dove。我们一起说：dove！" | dove | "对，就是它！它叫 dove。" | "没关系，Bunny 先说：dove。想说的时候再说。" |
| 2 描述 | "Is it on the grass or in the tree?" | grass | "对！在草地上，on the grass！" | "我看到它在草地上，on the grass。" |
| 3 句子 | "A dove on the grass. 你能说一说吗？" | 整句或一个词 | "说得真好！A dove on the grass." | "Bunny 说：A dove on the grass. 这是你的新卡片！" |

### 4.2 单轮对话的数据流

```
  Bunny 说出本轮台词（预合成音频）
              │
              ▼
  开始收音（最长 5 秒）
              │
              ▼
  ┌───────────────────────┐
  │ 语音识别 → 文本        │
  └───────────────────────┘
              │
              ▼
  ┌──────────────────────────────────────────────┐
  │ 回应判断                                      │
  │   含目标英文词 ............... EN             │
  │   含对应中文意思 ............. ZH             │
  │   没有声音 / 5 秒超时 ........ SILENT         │
  │   有声音但听不懂 ............. UNCLEAR        │
  └──────────────────────────────────────────────┘
       │          │           │            │
       ▼          ▼           ▼            ▼
     EN 台词    ZH 台词    SILENT 台词   "没听清，再说一次"
       │          │           │            │
       │          │           │      重试 1 次，仍 UNCLEAR
       │          │           │      则按 SILENT 处理
       └──────────┴─────┬─────┴────────────┘
                        ▼
             下一轮；3 轮结束后 → 得卡

  ※ 任一环节出错或超过 2 秒无结果：操作员按钮（EN / ZH / SILENT）直接接管
```

### 4.3 识别规则

- 只判断孩子说的话里有没有目标词，或者有没有对应的中文意思；不判断发音好坏，不打分。
- 中英混说都算回应，例如"它是 green 的"。
- 识别不到任何声音按"不说话"处理。识别到但听不懂时，Bunny 说"Bunny 没听清，我们一起再说一次：dove！"，最多重试一次。
- 唤醒词"Bunny"同时接受"邦妮""兔兔"等近似发音。

### 4.4 语音合成规则

- Bunny 用固定的童趣音色；中文和英文用同一个角色音色，英文发音标准。
- 英文单词前后各停顿约 0.3 秒，单词说两遍。
- 语速：白天正常偏慢。睡前绘本从第 1 页到最后一页逐渐放慢，音量也逐渐降低。

### 4.5 说话的禁忌

- 不纠正发音，不说"错了"。
- 不预告奖励，例如"再找 3 个就有大奖"。
- 不说让孩子愧疚或依赖的话，例如"你不来我会难过"。
- 夸具体做法（"你听到声音就马上找到了它"），不夸"聪明"。

## 5. 设备与屏幕交互

手机是大人在户外用的，iPad 是孩子在家用的，两者的界面按使用者来设计。所有界面都不需要认字：文字只是给大人看的辅助，孩子靠图形、颜色和声音理解。

### 5.1 手机（户外，大人操作）

- 打开即是取景画面，只有一个直径不小于 72pt 的拍照按钮，放在屏幕下方正中。
- 对话时，屏幕上方是 Bunny 的动画，有说话、倾听、鼓掌三种状态；下方显示当前英文词的大字和对应插图，方便大人跟着一起说。
- 一个"按住说话"的备用按钮，与拍照按钮颜色不同、位置不同。
- 得卡后显示 2 秒卡片动画，然后自动回到取景画面，提醒大人收起手机。
- 顶部显示今天已得卡数，如"3 / 5"。达到 5 张后拍照按钮变灰，Bunny 说"今天的探险卡收满啦"。

```
  ┌─────────────────────┐        ┌─────────────────────┐
  │ 3 / 5               │        │       (Bunny)       │
  │                     │        │    倾听中 ～～～     │
  │                     │        │                     │
  │    [ 取景画面 ]     │        │   ┌─────────────┐   │
  │                     │        │   │   [插图]    │   │
  │                     │        │   │    dove     │   │
  │                     │        │   └─────────────┘   │
  │  按住说话   ( ◉ )   │        │      按住说话       │
  └─────────────────────┘        └─────────────────────┘
       拍照状态                        对话状态
```

### 5.2 iPad（在家，孩子操作）

- 横屏使用。可点击区域不小于 60 × 60pt，相邻可点区域间隔不小于 16pt。
- **图鉴页**：卡片大图左右滑动，未找到的显示灰色剪影；只有"左右滑"和"点一下放大"两种手势。
- **绘本页**：全屏图片，下方一行字幕；播放时自动翻页，不需要操作。只有"播放 / 暂停"一个按钮，放在右下角。
- **睡前模式**：屏幕亮度降低、暖色；读完后自动黑屏，只保留声音。
- 不出现广告、弹窗、外链，也没有需要打字的地方。

```
  ┌───────────────────────────────────────────┐
  │                                           │
  │              [ 绘本插图 4:3 ]              │
  │                                           │
  │                                           │
  │  朵朵发现了一只斑鸠。A dove on the grass.  │
  │  ● ● ○ ○ ○ ○ ○                      [ ▶ ] │
  └───────────────────────────────────────────┘
                 iPad 绘本页（横屏）
```

### 5.3 在 Web Demo 中的呈现

手机和 iPad 都以设备外框的形式出现在网页上，3D 场景在背景中同步变化。真实设备不是必需的：手机拍照用预设的物品图片模拟，iPad 的翻页由网页自动完成或由操作员控制。

## 6. Web 展示与 3D 场景

网页以 16:9 全屏投到会场大屏。3D 公园占满背景，设备外框（手机或 iPad）浮在右侧三分之一，左下角是一行给评委看的说明字幕。

3D 场景有两个作用：

- 让评委一眼看懂孩子在哪里发现了什么；
- 让孩子把每张卡和公园里的一个位置联系起来，记得更牢。

### 6.1 画面布局（1920 × 1080）

```
  ┌──────────────────────────────────────────────────────────────────┐
  │  ① 出门  ② 发现  ③ 拍照  ④ 对话  ⑤ 得卡  ⑥ 回家  ⑦ 睡前   ← 进度条 │
  │                                                                  │
  │                                              ┌────────────────┐  │
  │                                              │                │  │
  │              3D 场景（全屏背景）              │   设备外框     │  │
  │        公园 / 客厅 / 卧室 / 记忆地图          │  手机 或 iPad  │  │
  │                                              │   约 560px 宽  │  │
  │                                              │                │  │
  │                                              └────────────────┘  │
  │                                               ▁▃▅▇▅▃▁ 语音波形   │
  │  评委字幕：这一幕在做什么、为什么这样设计（最多两行）              │
  └──────────────────────────────────────────────────────────────────┘
```

| 区域 | 位置 | 内容 |
| --- | --- | --- |
| 3D 场景 | 全屏背景 | 公园或室内场景，镜头随幕切换 |
| 设备外框 | 右侧，约宽 560px | 当前幕的手机或 iPad 界面 |
| 进度条 | 顶部 | 七幕的名称，当前幕高亮 |
| 评委字幕 | 左下角，最多两行 | 这一幕在做什么、为什么这样设计 |
| 语音波形 | 设备外框下方 | 孩子或 Bunny 说话时显示，标明是谁在说 |

### 6.2 3D 公园的内容

与《图片生成 Prompts》文档中的九样物品一致：

- 一片湖泊，湖上一座拱形石桥，湖里有一只鸭子游动。
- 一棵桂花树，有金色小花缓慢飘落的粒子效果。
- 一片草坪，草坪上一只珠颈斑鸠在走动，长椅脚边有一只蜗牛。
- 公园边缘有一段铁轨，一列绿皮火车每隔约 40 秒缓慢驶过一次。
- 一个小女孩角色和 Bunny 沿着小路走动。小女孩用卡通形象，与绘本中的主角一致。

```
              公园俯视（记忆地图）
  ═══════════════════════════════════════════  ← 铁轨（绿皮火车）
  
       ✿ 桂花树                      长椅
      (桂花飘落)                     ▭▭▭  @ 蜗牛
  
            ┌───────────────────┐
            │      湖 泊        │       ,,, 草坪 ,,,
            │   ⌒⌒ 小桥 ⌒⌒     │       ,,  斑鸠  ,,
            │        🦆 鸭子     │       ,,,,,,,,,,,,
            └───────────────────┘
  
   入口 ▶ ··········· 小路 ··········· 
  
   ★ = 孩子找到过的位置（得卡后升起）
```

**风格**：低多边形，加柔和材质（类似黏土质感），暖色调，和绘本的水彩风格颜色一致；不追求写实。

### 6.3 镜头

| 幕 | 镜头 |
| --- | --- |
| 1 出门 | 从公园入口外的远景开始，缓慢推进 |
| 2 发现 | 从全景飞到被发现的物体前，约 1.5 秒，物体轻微发光 |
| 3–4 拍照、对话 | 停在物体前，缓慢环绕 |
| 5 得卡 | 拉远到俯视的"公园地图"，物体位置升起一颗发光的星 |
| 6 回家 | 切换到客厅场景，窗外能看到远处的公园 |
| 7 睡前 | 切换到卧室场景，之后淡出到夜晚公园的俯视图 |

### 6.4 昼夜转换

从第 1 幕到第 5 幕，光线从下午的暖白色逐渐变成傍晚的橙色。第 7 幕切到夜晚：天空出现星星，桥上的灯笼亮起，火车窗户亮起暖黄色。

### 6.5 记忆地图

第 5 幕和第 7 幕都会出现俯视的公园地图，孩子找到过的位置各有一颗星。睡前绘本播放完后，镜头从地图上逐一掠过这些星星，最后停在月亮上。

这一设计利用了"把东西和位置联系起来更容易记住"的规律，让孩子对自己找到的东西形成空间记忆。

### 6.6 性能和兜底

- 在普通笔记本的 Chrome 中保持每秒 30 帧以上。
- 模型总大小不超过 15MB，首次加载不超过 10 秒。
- 所有模型和贴图提前打包在本地，不依赖现场网络。
- WebGL 不可用时，自动换成同构图的 2D 插图（来自《图片生成 Prompts》文档中的场景图），流程不受影响。

## 7. 技术架构

Demo 是一个本地运行的单页网页，中心是一个按七幕推进的流程控制器。语音识别的结果和操作员的按钮都交给它判断，再由它驱动 3D 场景、设备界面和 Bunny 的声音。所有内容提前打包在本地，现场网络断开也能完整演示。

### 7.1 组件关系

```
   输入                         控制                          输出
  ┌──────────────────┐
  │ 孩子说话          │
  │ 麦克风 / 唤醒词   │
  └────────┬─────────┘                                ┌──────────────────────┐
           │                                    ┌────▶│ 3D 场景               │
           ▼                                    │     │ 公园/客厅/卧室/记忆地图│
  ┌──────────────────┐      ┌────────────────┐  │     └──────────────────────┘
  │ 语音识别          │      │  流程控制器     │  │     ┌──────────────────────┐
  │ 判断 EN/ZH/SILENT │─────▶│  七幕状态机     │──┼────▶│ 设备外框              │
  └──────────────────┘      │  决定 Bunny 说  │  │     │ 手机/iPad 界面、字幕  │
                            │  什么、画面切到  │  │     └──────────────────────┘
  ┌──────────────────┐      │  哪里           │  │     ┌──────────────────────┐
  │ 操作员面板        │─────▶│                │  └────▶│ Bunny 的声音          │
  │ 推进、选择回应    │      └───────▲────────┘        │ 预合成音频 → 会场音响 │
  └──────────────────┘              │                 └──────────────────────┘
                                    │
  ┌─────────────────────────────────┴───────────────────────────────────────┐
  │ 离线内容包：物品数据、台词、预生成语音、绘本图片、3D 模型（不依赖现场网络）  │

```

操作员面板和语音识别是同一件事的两条路：识别准确时自动推进，识别出错或太慢时由操作员接管，控制器不区分两者。

  └──────────────┘                  └──────────────────┘
```

### 7.3 流程控制器的状态

```
  ACT1_LEAVE
      │ 任务语音播完
      ▼
  ACT2_DISCOVER ◀──────────────────────────────┐
      │ 唤醒词 / 操作员 next                     │
      ▼                                         │
  ACT3_PHOTO                                    │
      │ 拍照完成 → 识别物品（失败 → 神秘卡）      │

### 7.4 技术选型建议

| 部分 | 建议 | 说明 |
| --- | --- | --- |
| 3D 场景 | three.js，glTF 模型 | 低多边形模型体积小，笔记本也能流畅运行 |
| 页面 | 单页网页，全屏运行在 Chrome | 展示页与操作员面板是两个页面，通过本地连接同步 |
| 语音识别 | 支持儿童声音和中英混说的在线服务；离线时由操作员接管 | 赛前用小作者的声音实测识别效果 |
| 语音合成 | 预先合成全部台词，存成音频文件 | 台词固定，预合成最稳定，没有延迟 |
| 绘本 | 赛前用多模态模型生成并人工检查，现场直接播放 | 现场实时生成列为 P2 |

## 10. 现场演示要求

Demo 有两种模式，开场前选定，演示中也能随时切换：小作者状态好就用现场互动模式；她不上台或中途想下台，就切到自动播放模式，画面无缝衔接。

| | 现场互动模式 | 自动播放模式 |
| --- | --- | --- |
| 孩子是否参与 | 是，用语音和 Bunny 对话 | 否 |
| 物品数量 | 2 样（珠颈斑鸠、桂花） | 4 样 |
| 时长 | 约 6 分钟 | 约 3 分钟 |
| 推进方式 | 操作员按孩子的反应推进 | 按预设时间自动推进 |
| 孩子的声音 | 现场麦克风 | 预录的音频 |

### 10.1 操作员面板

- 与展示页分开，在操作员自己的笔记本或平板上打开，不投到大屏。
- 一键推进到下一幕或下一轮对话。
- 每轮对话有三个回应按钮："说了英文""说了中文""没说话"。语音识别出错或延迟时，操作员直接点按钮，Bunny 按对应的台词回应。
- "识别失败"按钮：切换到神秘卡流程。
- "切换到自动播放"按钮：从当前幕接着自动演完。
- 每个按钮都有键盘快捷键，便于在现场光线暗时操作。

```
  ┌──────────────────────────────────────────────┐
  │ 当前：④ 对话 · 第 2 轮 · 物品：珠颈斑鸠        │
  │ 识别结果："草地" → ZH                          │
  ├──────────────────────────────────────────────┤
  │ [1] 说了英文   [2] 说了中文   [3] 没说话       │
  │ [N] 下一步     [B] 上一步     [M] 神秘卡       │
  │ [A] 切换到自动播放                             │
  └──────────────────────────────────────────────┘
```

### 10.2 对评委的说明

现场为了保证孩子的体验，Bunny 的回应由操作员在预设内容中选择；绘本是赛前用小作者在公园的真实发现生成的。在开场或答辩时主动说明这一点。

### 10.3 现场设备与环境

- 大屏输入 1920 × 1080，网页全屏；电脑音频接入会场音响。
- 给孩子用手持麦克风或指向性桌面麦克风，不用头戴式；麦克风靠近孩子，但不对着她的脸。
- 舞台一角布置迷你公园：一盆小桂花树（或桂花枝）、一只珠颈斑鸠的毛绒玩偶。孩子拍它们时，屏幕上出现对应的识别结果。

### 10.4 应急预案

| 情况 | 处理 |
| --- | --- |
| 孩子不愿上台 | 直接用自动播放模式，同时播放她赛前在公园的视频 |
| 孩子说话被识别错 | 操作员点对应的回应按钮 |
| 孩子不说话 | 按"没说话"处理，Bunny 说出答案，照样得卡 |
| 3D 卡顿或黑屏 | 自动或手动切换到 2D 插图版 |
| 网络中断 | 所有内容已离线打包，不受影响 |
| 音响没声音 | 用笔记本自带扬声器，同时打开评委字幕 |

## 11. 验收标准与范围外

比赛前至少完整彩排两次：一次用现场互动模式（最好有小作者参与），一次用自动播放模式。下面每一项都通过才算可以上台。

### 11.1 验收标准

- [ ] 自动播放模式从头到尾无需任何操作，3 分钟内完成，无报错。
- [ ] 现场互动模式下，三种回应（英文、中文、不说话）在每一轮都能走通。
- [ ] 操作员按任意回应按钮后，Bunny 在 1 秒内开始说话。
- [ ] 语音识别的回应延迟不超过 2 秒；超过时操作员按钮可以接管。
- [ ] 3D 场景在演示用电脑上保持每秒 30 帧以上，九样物品都能被镜头飞到。
- [ ] 每次得卡后，记忆地图上对应位置都出现星星。
- [ ] 绘本按得到的卡片正确生成页数和内容，自动翻页与朗读同步。
- [ ] 断开网络后重新加载，完整流程仍能演示。
- [ ] 关闭 WebGL 后，2D 插图版能完整演示。
- [ ] 画面和语音里没有孩子的全名，绘本主角是卡通形象。

### 11.2 不在这次 Demo 范围内

- 家长端功能（探险报告、分享、时长设置）。
- 账号、登录、数据存储。
- 发音评测和学习数据统计。
- 九样以外的物品识别。
- 真实的手机 App 或小程序；手机和 iPad 只在网页中模拟。

## 12. 待确认问题

以下问题会影响开发工作量或现场安排，越早确定越好。

- [ ] 比赛给 Demo 的时长是多少？如果少于 6 分钟，现场互动只走一样物品。
- [ ] 现场是否提供稳定的网络？这决定语音识别能否使用在线服务。
- [ ] 语音识别和合成用哪家服务？需要对儿童声音、中英混说有较好效果，并在比赛前用小作者的声音实测。
- [ ] 小作者在 Demo 中用什么称呼（小名）？
- [ ] 赛前去公园实拍的时间，以及她的绘本由谁来生成和检查？
- [ ] 会场大屏的分辨率和比例，以及是否能提前进场彩排？
- [ ] 3D 模型自己做还是用现成素材？现成素材需要确认授权，并统一成同一种风格。
